# jverification 功能与平台差异

2026-10-09 Native receiver 版本：Maven `0.1.5`、Git Pod `0.1.5`（内部 `0.1.5`），HAR 未改。具体发布与远程验收结果见[对应 Release](https://github.com/gycrosskit/jverification/releases/tag/0.1.5)；下方历史版本记录只证明其注明范围。

适用日期：2026-10-08。发布基线为 `0.1.4`，本轮从 `3dab08016c4fca4b21d8548f90cd463ae4d3e4e2` 补充测试与文档，生产实现不变，不新增制品版本；HAR保持 `0.1.0`。新增测试直接编译实际 Android driver 文件，Android/厂商 I/O 使用受控替身；另以真实厂商依赖编译 Android target，不能据此声明真实运营商/授权页通过。当前安装示例仍使用已发布0.1.4。

## 产物与职责

| 模块/产品 | 实际职责 |
|---|---|
| `jverification-core` | JVerificationClient / Driver / Result，Android SDK driver、iOS闭包driver；JVM/OHOS core不自带运营商SDK驱动。 |
| `jverification-kuikly` | Android/iOS/OHOS JVerificationModule发送端；AndroidJVerificationModule与可选Pod Swift JVerificationModule接收端连接既有driver/client，页面dispatcher由宿主注入。 |
| `GycJVerificationNative` | iOS15+ Git Pod Swift client，默认Native，可选Kuikly subspec；JVerification3.4.7/JCore5.5.1、OpenKuiklyIOSRender2.28.0；无Swift Package。 |
| `@gycrosskit/jverification-native` | API22 HAR，GycJVerificationService/Module，@jg/verify1.2.2；原生工厂传AppKey/UIContext。 |

构建边界：[core构建](../jverification-core/build.gradle.kts)、[Kuikly构建](../jverification-kuikly/build.gradle.kts)、[模块清单](../settings.gradle.kts)、[OHOS SDK配置](../ohos/build-profile.json5)。

除上表明确的 UI 入口外，本库没有独立 CMP 页面模块。CMP 沿用原生driver/client注入；Android/iOS Kuikly由本库Native receiver接线，宿主仅注册工厂、提供配置并保持平台回跳。新增receiver不表示品牌/设备业务已验收。

## 五入口功能矩阵

“原生实现，宿主注入”表示平台能力已有源码，CMP/Kuikly由宿主适配接入；“OHOS Module已实现”表示已有Kotlin/ArkTS调用链。矩阵说明功能接入边界，实际行为验证见下方验证范围。

| 功能/API组 | CMP Android | CMP iOS | Kuikly Android | Kuikly iOS | Kuikly OHOS |
|---|---|---|---|---|---|
| 同意门控 / initialize / prepare预取号 | 原生实现，宿主注入 driver | 原生实现，宿主注入 bridge+Swift | Native receiver已实现；宿主注入配置/回跳，未设备验收 | Native receiver已实现；宿主注入配置/回跳，未设备验收 | OHOS Module已实现+service |
| authenticate / opened / token结果 | 原生实现，宿主注入厂商页 | 原生实现，宿主注入厂商页 | Native receiver已实现；宿主注入配置/回跳，未设备验收 | Native receiver已实现；宿主注入配置/回跳，未设备验收 | OHOS Module已实现厂商页 |
| cancel / revoke / cache / close | 原生实现，宿主注入 | 原生实现，宿主注入 | Native receiver已实现；宿主注入配置/回跳，未设备验收 | Native receiver已实现；宿主注入配置/回跳，未设备验收 | OHOS Module已实现 |
| 品牌AppKey/样式/采集/后端换票 | 宿主注入/未验收 | 宿主注入/未验收 | 宿主注入/未验收 | 宿主注入/未验收 | 宿主注入/未验收 |

## 公开 API 组

- `JVerificationClient.prepare(consentGranted)` / `authenticate(consentGranted,opened)` / `cancel()` / `revokeConsent()` / `close()`。
- `JVerificationDriver.initialize/preLogin/authenticate/cancel/clearPreLoginCache/close`是底层驱动合同；cache清理由撤销流程或driver入口执行，不虚构client的clearPreLoginCache公开方法。
- 三端 `JVerificationModule`实现Driver，页面退出先client.close再module.dispose；Swift原生client有prepare/initialize/preLogin/authenticate等入口。

## API 合同与差异分类

| 分类 | 具体输入 / OS / SDK边界 | 调用方应如何处理 |
|---|---|---|
| 厂商限制 | Android JVerification3.4.8/JCore5.5.6；iOS3.4.7/5.5.1；OHOS@jg/verify1.2.2。 | 不同SDK/运营商能力与错误码不能凭共同client推断等价；vendorCode保留、凭据content不直接返回。 |
| 组件边界 | prepare默认初始化/预取号各10秒；authenticate整体120秒，SDK取Token/拉页15秒。 | prepare不打开授权页；authenticate(true)自动初始化。event2仅一次opened，event1关闭；6000且非空白token才TOKEN，不能以opened当成功。 |
| 组件边界 | 一进程一个AppKey/活动SDK owner；同client并发BUSY。 | 旧generation、撤销/取消/close后的token/opened不交付；清理用NonCancellable。底层init未必可取消，不表示卸载SDK。 |
| 宿主职责 | Android API24+当前Activity、iOS15+、OHOS目标/兼容API22。 | 提供真实同意、AppKey、UIConfig/条款/采集策略、应用登记和当前UIContext；未同意不init。Token仅交宿主后端换票，不创建账号/存储token。 |
| 未验收 | 真实SIM/运营商网络、厂商认证页/隐私、后端换票、多品牌AppKey。 | 源码编译/mock证明回调合同，不证明一键认证成功或合规授权。 |
