## 本地行为检查

以下命令从仓库根目录执行。配置`ANDROID_HOME`与可运行Gradle的JDK；Kotlin/Native测试需要macOS、Xcode及iOS Simulator运行环境。Node测试转译真实ArkTS源码并使用受控SDK替身，`TYPESCRIPT_PATH`可指定已有TypeScript模块。

```sh
bash gradlew :jverification-core:jvmTest :jverification-core:compileDebugKotlinAndroid --max-workers=1
node verification/ohos-behavior.cjs
bash verification/swift-callbacks/verify.sh
```

JVM target同时执行实际`AndroidJVerificationDriver`，仅Android/SDK边界由测试替身提供；Android编译另核对真实厂商API，二者不代表运营商/授权页实机验收。

只运行受影响目标；需要确认本轮真实执行时加`--rerun-tasks`，不要把`UP-TO-DATE`算成新执行。平台测试结果XML位于`jverification-core/build/test-results/`。这些测试不调用真实分享、认证、拨号或定位业务。

## 原生产物与独立消费

HarmonyOS工具链需要DevEco SDK、ohpm与hvigorw。在`ohos/`目录执行：

```sh
ohpm install --all
hvigorw --mode module -p module=JVerificationNative@default -p product=default assembleHar --no-daemon
```

安装与公开API消费工程按[接入指南](接入指南.md)和[README](../README.md)执行；`scripts/verify.sh`是更广的维护检查，不是每次小改动的必跑全套。构建/本地HAR消费不等于OHPM Registry或新候选远程消费。Maven、Swift/Pod与HAR按各自版本验证。
