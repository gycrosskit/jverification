# JVerification 开发与验证

消费者用法见 [README](../README.md) 和[接入指南](接入指南.md)，历史验证见[结果记录](../verification/结果.md)。在仓库根目录执行 `bash scripts/verify.sh`；HAR 检查使用 `bash scripts/verify-har.sh`，需要 Android SDK、macOS / Xcode、CocoaPods 及 DevEco SDK。

本地全变体 Maven 输出到 `build/maven`；独立消费者默认从 JitPack 获取正式坐标。本地验收添加 `-PlocalArtifacts=true`，只消费打包坐标，不使用源码替换；此结果不能当作远程验收。

Maven 在 macOS 构建，按不可变版本 Tag 上传 GitHub Release 归档。`release-pack.py` 排除 macOS AppleDouble，`release-checksums.txt` 必须记录真实归档 SHA-256。JitPack 安装入口拒绝缺少校验的版本，metadata 修复只处理本库路径。

## 已有验证范围

- JVM / iOS 共用测试覆盖同意门控、预取号、并发、取消/撤销、超时、关闭、Token 脱敏及 opened 与终结结果顺序。
- Android AAR、iOS/OHOS Kotlin 编译、Swift 原生 Pod 编译链接及 KMP 接线 typecheck。
- ArkTS 实际服务/模块源码与 SDK 替身验证，HAR 打包及独立消费。
- JitPack 正式版本独立消费与 iOS Simulator Framework 链接；OHPM Registry 精确版本安装和独立 HAR 编译。

这些检查不证明运营商认证通过。三端真实 SIM、登记应用、授权页打开、宿主 loading、取消/返回/超时/旋转/销毁、采集配置、撤销同意和服务端换票仍需设备与后端验收。不要用 SDK mock 或 Framework 链接结果代替真实 Token 流程。

HAR `0.1.0`、Maven / Git Tag `0.1.1` 和 Podspec 内部版本 `0.1.0` 是不同版本层级；Pod 尚未发布到 CocoaPods Specs，原生消费使用指定 Git Tag。
